# P02 Matched Baseline Harness

Status: **P02 closeout candidate / SG-000005**

P02 makes baseline comparison mechanics explicit before GAX v0 exists. The harness is not a leaderboard and the synthetic smoke fixtures are not clinical evaluation.

## Why this phase exists

A medical decision paper can appear to compare models fairly while silently changing:

- candidate action wording or membership;
- test denominators;
- parsing/failure treatment;
- calibration data;
- truncation;
- caching;
- timing boundaries;
- model revisions.

P02 prevents those differences from being hidden behind one final table.

## Adapter contract

Every adapter exposes an immutable `AdapterIdentity` containing:

- adapter name/version;
- deterministic-mode declaration;
- model ID/revision when relevant;
- tokenizer revision when relevant;
- upstream/source revision when relevant;
- artifact digest for imported prediction files.

Every adapter implements:

```text
prepare(items)
predict(item) -> Prediction
```

`prepare` may validate the complete candidate set, cache deterministic resources, and freeze run-level assumptions. It must not inspect hidden test labels to tune behavior.

## Offline controls

P02 includes only non-clinical infrastructure controls as built-in baselines:

- **uniform** — equal probability over the exact caller-provided action set;
- **lexicographic** — deterministic probability 1.0 on the lexicographically smallest action ID;
- **prediction-file** — immutable import of externally generated typed predictions.

These controls exist to qualify the harness. They are not intended as meaningful medical baselines.

## Failure discipline

Every requested item remains visible.

An adapter preparation failure marks every requested item as failed at stage `prepare`.

An item-level failure records:

- item ID;
- stage;
- exception type;
- message;
- measured adapter duration.

If any requested item fails, the runner does **not** compute a complete-run metric table from the surviving items.

This preserves the P01 no-silent-drop denominator contract.

## Evidence packet

A baseline run writes:

```text
packet/
  manifest.json
  predictions.jsonl
  failures.json
  timings.json
  metrics.json
```

The manifest binds:

- GAX repository revision and dirty-tree flag;
- adapter identity/revisions;
- benchmark SHA-256;
- command;
- seed;
- calibration revision;
- runtime metadata;
- requested/completed/failed counts;
- hashes of emitted packet files.

The packet ID is a canonical hash of stable run identity metadata. Raw timing values are retained as evidence but are not used to make cross-hardware superiority claims.

## Metrics

Metrics are generated by the canonical P01 implementation only when:

1. every requested item completed successfully; and
2. the benchmark labels are sufficient for the requested evaluation.

If evaluation itself fails, `evaluation_error` is recorded and the CLI exits non-zero.

No alternate metric implementation is allowed inside an adapter.

## External baseline registry

`registry/baselines.json` separates source availability from qualification status.

Current states include:

- `qualified-offline` — GAX-owned deterministic infrastructure controls;
- `adapter-qualified` — source/license/protocol adapter is frozen and tested, but no real-model benchmark result is implied;
- `external-pending` — a real model identity is frozen but matched benchmark execution remains pending;
- `blocked` — inclusion depends on an unresolved access or terms constraint.

At P02 closeout, every required baseline class has an explicit source or model identity, immutable revision, access status, license, and qualification state. Jev remains explicitly blocked rather than silently omitted.

Real-model execution is intentionally deferred to **P08 Full Paper Evaluation** after the benchmark, baseline revisions, model revisions, calibration procedure, and hardware protocol are frozen. This prevents test-set peeking and avoids making zero-founder-cost external compute a prerequisite for implementing GAX v0.

## CLI

Offline control:

```bash
gaxbench baseline-run \
  --items tests/fixtures/items.jsonl \
  --adapter uniform \
  --output-dir artifacts/p02/uniform-smoke \
  --repo-revision <git-sha> \
  --seed 0
```

Immutable imported predictions:

```bash
gaxbench baseline-run \
  --items <items.jsonl> \
  --adapter prediction-file \
  --prediction-file <predictions.jsonl> \
  --adapter-name <name> \
  --adapter-version <version> \
  --model-id <model-id> \
  --model-revision <immutable-revision> \
  --output-dir <packet-dir> \
  --repo-revision <git-sha>
```

Registry validation:

```bash
gaxbench baseline-registry
```

## Timing

P02 timing measures the adapter `predict` call per item.

It does not by itself prove end-to-end serving superiority because:

- preprocessing boundaries can differ;
- model load time is separate;
- caching can differ;
- hardware can differ;
- concurrent serving can differ.

Paper speed claims require the matched protocol in `docs/research/REPRODUCIBILITY.md`.

## P02 exit gate

P02 may close only after:

- deterministic offline suite passes;
- registry/schema validation passes;
- evidence packets retain all failures and reproduce smoke metrics;
- exact-head Linux/Windows Python 3.11/3.12 CI passes;
- implementation merges normally;
- post-merge CI passes;
- canonical closeout advances the frontier to P03.

External-model qualification proceeds in later governed P08 grains without inventing results in P02. P02 establishes the comparison contract; P08 executes the frozen comparison.
