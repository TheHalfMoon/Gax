# Reproducibility and Claim Discipline

GAX treats every public numeric claim as an artifact-backed statement.

## Evidence packet

Every run eligible for a paper table or README claim must bind:

- git commit SHA;
- dirty-tree state;
- model ID and immutable revision;
- tokenizer revision;
- dataset IDs and immutable revisions;
- split manifest hash;
- transform revision;
- command line/config;
- seed(s);
- package lock/environment export;
- hardware;
- driver/runtime versions;
- start/end timestamps;
- raw predictions or privacy-safe sufficient statistics;
- metric implementation revision;
- stdout/stderr logs;
- failure/exclusion counts.

## Directory target

```text
artifacts/
  runs/<run-id>/
    manifest.json
    metrics.json
    predictions.*        # only where redistribution is allowed
    environment.txt
    command.txt
    logs/
  tables/
  figures/
```

Large artifacts can live in release/Hugging Face storage with immutable references rather than Git, but the manifest stays in the repository.

## Test freeze

Final test evaluation follows:

1. approve benchmark version;
2. sign/freeze split manifest;
3. freeze evaluation code;
4. freeze baseline/model revisions;
5. freeze calibration procedure;
6. run final evaluation;
7. do not tune on failures.

If code changes after test evaluation in a way that can affect outputs, increment the experiment revision and rerun.

## Randomness

- record every seed;
- use multiple training seeds for claims sensitive to initialization/order;
- report mean and dispersion;
- deterministic inference where technically possible;
- disclose nondeterministic kernels.

## Calibration discipline

Calibration parameters are fit on a calibration/dev split only.

Report separately:

- raw probabilities;
- calibrated probabilities;
- calibration method;
- calibration-set size;
- calibration revision.

No test-set temperature tuning.

## Benchmark failure policy

A failed inference is not silently dropped.

Report:

- total requested;
- completed;
- timeout;
- OOM;
- parse/interface failure;
- invalid output;
- exclusion with reason.

Typed models should have zero out-of-schema answers by construction; wrong in-schema answers still count as wrong.

## Performance benchmarking

Speed claims require:

- same hardware for direct model comparisons where feasible;
- same batch/concurrency definition;
- warm/cold state reported;
- input-length distribution;
- number of candidate actions/questions;
- preprocessing included/excluded explicitly;
- cache hit/miss status;
- at least p50 and p95.

When hardware differs, report absolute measurements in separate rows and do not claim direct speed superiority.

## Statistical analysis

Default:

- paired bootstrap confidence intervals for paired examples;
- multiple seeds for training comparisons;
- risk-coverage curve with AURC;
- calibration reliability plot plus ECE/NLL/Brier;
- exact sample counts.

Any significance test must name the test, sidedness, alpha, and correction if multiple primary tests are used.

## Claim gate

A claim enters the README/paper only when:

- the source run has a complete evidence packet;
- the metric is generated by versioned code;
- the relevant baseline uses a matched protocol;
- uncertainty is reported when appropriate;
- limitations are known;
- no unresolved leakage/license issue affects the result.

## External review

Before release:

- run repository code review with Alibaba Open Code Review for accounting/review assistance;
- use Jev review/decision tooling where applicable as an auxiliary review, never as the sole scientific validator;
- require human inspection of research claims and benchmark methodology;
- do not use CodeRabbit as qualification evidence for this project.

Automated review does not replace replication.

## Negative results

Negative or failed research runs remain in the experiment ledger with:

- hypothesis;
- configuration;
- result;
- failure reason;
- decision (retain/reject/retest).

The manuscript may include negative results when they clarify the design space.

## Reproduction levels

- **L0 smoke:** package imports, tiny deterministic fixture.
- **L1 benchmark:** released weights reproduce reported inference metrics.
- **L2 fine-tune:** accessible tutorial reproduces a small-domain adaptation.
- **L3 paper:** full training/evaluation regenerates main tables given required compute/data access.
- **L4 external:** independent party reproduces at least one central result.

The arXiv release should reach L2 publicly and provide the materials required for L3; L4 is a post-release target.
